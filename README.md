# A back-tested screening workflow for lithium and copper mining investments

Code and data accompanying the paper *"From reference-class cost priors to
investment choices: a back-tested screening workflow for lithium and copper
projects"* (Jef Caers, Stanford Mineral-X; under submission to *Mineral
Economics*).

The workflow screens a greenfield mining investment — **enter, fund a feasibility
study, or walk** — from information public at the decision date. It blends a
reference-class capital-overrun prior with the project's own engineering estimate,
feeds that into a scenario-driven Monte-Carlo NPV, and reduces the NPV
distribution to a tail-weighted decision statistic (RAV). A country-risk module
adds policy-intervention effects and predicts activation from a latent
political-economic regime. Everything is **back-tested under leakage control** on
ten lithium projects (2010–2019) and eleven Chilean copper projects (2008–2019),
and audited against three documented trading-house decisions.

This repository reproduces every quantitative result, table, and figure in the
paper. All scripts are deterministic (fixed random seeds) and self-contained: they
carry their project data inline and depend only on NumPy, SciPy, and Matplotlib.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate     # optional
pip install -r requirements.txt                       # numpy, scipy, matplotlib

# reproduce a headline result:
python backtest_copper.py            # copper cohort: calibration, ranking, audit
python causal_validation_multiyear.py# held-out causal test (the +0.29 nats result)

# regenerate all figures into figures/ and the results dump into data/:
python make_results_figs.py
python make_fig1_workflow.py         # (and make_fig2 … make_fig7)
```

Scripts are location-independent — each resolves its inputs relative to its own
file — so you can run them from any working directory (`python /path/to/backtest_copper.py`).

## Four independent pillars

The code is four self-standing pillars that share vocabulary but not imports. You
can run any pillar on its own.

1. **Cost / valuation engines** — `excel_engine_port.py` is the reference DCF+RAV
   implementation (and the source of the Sobol sensitivity table);
   `stage_a_engine.py` is the forward-looking causal model that answers
   do()-intervention and counterfactual (RIGI) questions; `driver_model.py`
   quantifies which pre-decision drivers explain capital overruns.

2. **Copper cohort** — `backtest_copper.py` is the base study; `copper_sensitivity.py`
   and `ablation_ladder.py` re-run it under parameter sweeps and the ablation
   ladder. Each is runnable directly.

3. **Lithium cohort** — `lithium_engine/backtest_validation.py` is the lead
   back-test; `backtest_metrics.py` and `loss_sensitivity.py` add the full metric
   suite and loss-weight sensitivity; `ablation_ladder_lithium.py` is the ablation.

4. **Country-risk / causal module** — a latent-regime HMM (`hmm_regime.py`) fit to
   an observable indicator panel (`indicator_panel.py`), a policy-event panel that
   yields probit activation hazards (`activation_panel.py`), and three held-out
   validation runs that form a deliberate progression (static → one-step →
   multi-year belief). `causal_validation_multiyear.py` is the citable result;
   `verify_multiyear.py` re-derives it with an exact dynamic program and a
   400k-path Monte Carlo to confirm the marginal-belief shortcut does not inflate
   the pass.

A suggested full run-order is in `results/` (each `*_results.txt` is the reference
stdout for one script); within a pillar, run the base study first, then its
sensitivity/ablation/metric scripts.

## Data

The `data/` directory holds derived result tables and the policy-event register;
`data/DATA_DICTIONARY.md` documents every field. The engines do **not** read these
files — each engine carries its project data (price paths, cohort definitions,
overrun analogs, regime codings, policy events) inline as Python literals, so a
script is a complete, auditable statement of its own inputs. `rf_data.json` is a
produced artifact (rewritten by `make_results_figs.py`).

**Data status.** The policy-event primary-source citations
(`policy_event_table.json`, `Policy_Event_Register.md`) are marked `[CHECK]`
pending final citation before journal submission; the event coding itself is
complete. The copper curation register and the era-sourcing memo — internal
working documents with candid review notes — are **not** part of this public
release; the per-case confidence tier they assign is preserved in the `conf`
fields of the data tables, and sanitized versions are available on request.

## Reproducibility notes

- **Determinism.** Every stochastic script fixes its seed (`numpy.random.default_rng`
  seeds: 0/3/5/7/11/23 across scripts). Re-running yields identical numbers on the
  same NumPy build; minor last-digit drift can occur across NumPy/BLAS versions.
- **Monte-Carlo sizes.** Back-tests use 2,000 trials; the Olaroz worked example and
  intervention overlay use 3,000; the verification Monte Carlo uses 400,000 paths.
  A full run of all scripts takes a few minutes on a laptop.
- **No network, no external data downloads.** Everything needed is in the repo.
